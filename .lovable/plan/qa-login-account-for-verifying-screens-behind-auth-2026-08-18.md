# QA login account for verifying screens behind auth

Setup and verification only. No feature code changes.

## What gets created

1. **A QA Claim Buddy workspace** — its own workspace row, its own company profile ("QA Test Roofing"), completely separate from Global Contractor Network. No GCN company membership, no super-admin flag.
2. **A QA user** — an obvious QA email (e.g. `qa+claimbuddy@…`), password generated by me and stored as project secrets `QA_LOGIN_EMAIL` and `QA_LOGIN_PASSWORD`. The password is never printed in chat; I read it from the secrets when logging in. Email pre-confirmed so sign-in works immediately.
3. **One complete demo inspection**, all fake data:
   - Job/property: fictional homeowner at a made-up address
   - Saved roof measurement (footprint + labeled edges + squares)
   - Completed roof takeoff answers
   - A few placeholder photos
   - A report record and an estimate with line items

## Isolation check (runs before anything else is reported as done)

Access control today is workspace-scoped for Claim Buddy (`cb_workspace_ids()`) and company-scoped for Global Contractor (`auth_company_id()`), so a user with only the QA workspace and no GCN profile/company should see zero GCN rows. I will confirm this empirically, signed in as the QA user, by querying the GCN job/property/estimate tables and the Claim Buddy job list through the app's own client. If anything from GCN is visible, I stop, change nothing else, and report it as a security bug.

## Login proof

Sign in with the QA credentials in the sandbox browser at a 390px viewport, open the seeded inspection's roof takeoff screen, screenshot it, and report the actual list of sections top to bottom as rendered.

## Technical notes

- User created through the Auth admin API with `email_confirm: true`; password generated with the secret generator and written straight to project secrets.
- Seed rows inserted into `cb_workspaces`, `cb_workspace_members`, `cb_companies`, `cb_jobs`, `cb_measurements`, `cb_takeoffs`, `cb_photos`, `cb_reports`, and `estimates` (via `cb_job_id`).
- Isolation verified as the QA user (anon key + real session), not with a service-role client, so RLS is actually exercised.
- Playwright script kept under `/tmp/browser/`, credentials read from env, never echoed or screenshotted.
- No changes to any route, component, or library file.
